# 源码阅读与运行说明

当前仓库保留了原工程拆出的源码布局。以下内容根据当前文件核对，不将原工作环境的运行结果等同于独立克隆后的可用性。

## 建议从哪里读

只想了解流程时，可直接阅读项目首页和演示指南；离线图解需下载`docs/`目录后用浏览器打开`overview.html`，GitHub文件页主要用于查看其源码。

- 页面与流程：`frontend-src/src/DueDiligenceShell.tsx`及相邻组件。
- 服务入口：`due_app/main.py`，安装各业务模块路由。
- 案件与来源：`store.py`、`diligence.py`、`answers.py`。
- 答案候选与补问：`extraction.py`、`followups.py`。
- 辅助测算：`farmer_model_v2.py`及其路由。
- 报告与导出：`reports.py`、`report_model_v2.py`。

以上模块路径除前端外均相对于`due_app/`。

## 扩展到其他问询场景

项目介绍面向各类问询与访谈，当前代码仍保留具体行业实现：案件创建约束、问卷字段、来源Schema、辅助测算和报告模板需要一起适配。替换页面标题或提示词不能自动完成跨场景支持。

扩展时先确定问题目录、答案结构、来源与核验状态，再接入场景规则和报告模板。通用问询不一定需要额度、评分或计算模块；当前`farmer_*`模块属于已有行业示例。

## 独立运行仍需补齐什么

1. **规则与演示资源**：服务读取`due_app/data/`下的问卷、Schema、合成案例、模型规则及报告模板。当前快照未包含这些文件；部分模型还检查版本和哈希，不能用空文件替代。
2. **共享录音组件**：服务初始化引用`shared_recording_core`，当前仓库未包含其实现。
3. **专用前端入口**：构建配置引用`due-diligence.html`，当前快照缺少该入口。输出路径仍指向原工程的相邻目录，需先适配当前检出位置。
4. **运行环境**：PowerShell启动脚本寻找相邻工程中的Python环境。依赖见`requirements*.txt`和`frontend-src/package.json`；语音识别另需匹配的本地运行时与模型。
5. **答案提取配置**：服务初始化会创建提取适配器，缺失或不合格的配置可能阻止启动。排查时不要把实际密钥粘贴到源码或Issue。

因此本页不提供未经验证的“一键启动”命令。配套资源与目录适配完成后，应在全新的虚构数据目录检查启动、页面、报告导出与停止流程，再整理可复现的安装指南。

## 模型与数据流

案件数据库、报告与录音归档使用本应用的数据目录，HTTP服务默认绑定本机。运行位置与模型处理位置需分别判断：

- 补问模块包含按案启用的本地模型调用。
- 答案提取模块支持配置的本机代理，也包含外部模型接口路径。
- 配置外部模型并执行相应功能时，所选访谈原话与相关题目可能发送到该模型服务。
- 运行策略接口中的静态标记，不能替代对实际配置与请求路径的核对。

本次截图未调用模型服务，未导入现有案件数据库或录音。模型候选、人员确认、事实核验与辅助计算保持不同职责。

## 检查应证明什么

`tests/`提供模块检查入口，部分检查同样依赖配套数据与原工程资源。应记录对应提交、环境、命令及结果，不从测试文件数量推算通过数量。

技术检查用于核对数据关联、错误处理与计算一致性。场景问题目录的适用性、语音质量、AI建议有用性和报告语义，需要各自的评审证据。
